## 1. Why
The statistics review of the results note (`review-results.txt`, MUST 6; checked in the code, `JUDGEMENT-results.md`) found two quantities that the design promised and the stamped code did not save:
1. Qualifying sessions per labelling (DESIGN section 4: "The number of qualifying sessions, N_progression and N_neurons are saved for every permutation and reported"; RESULTS section 0 item 4). `cell_tests.one_labelling` returns only `n_prog` and `n_neurons`; `n_qual` and the qualifying sessions (from `cellport.build_design`) are dropped.
2. The z-test for the true template (DESIGN section 5a: "reported for the true template too (G11, descriptive)"). The gate saved the G11 means only.

## 2. What is added (two new files; no stamped file changes)
`code/run_cell_a3.py` and its check `code/test_run_cell_a3.py` (output `test_run_cell_a3.out`, synthetic sessions only).
- **Design replay.** For each of the five tests and each labelling (observed and P = 1,000 permutations), the labelling is rebuilt from the stamped stream `cell_tests.rng_for(purpose, kind, index)`, permutation step only, and `cellport.build_design` gives `n_prog`, `n_neurons` and `n_qual` per region. No decoder is run. The replayed `n_prog` and `n_neurons` are compared with the saved `design_obs` and `design_null` of each `test-*.json`; the number of matching permutations is reported. Per region the replay saves the indices of the qualifying sessions (their number is the quantity DESIGN section 4 names) and `n_qual`, the qualifying neurons. If a labelling's replayed `n_prog` or `n_neurons` differs from the saved value, its qualifying counts are not used and the number of such labellings is reported.
- **True-template z-test.** `cell_gate.gate_draws` on the true-template labels with the G11 settings (100 draws per region, purpose code 22, the adopted variant `as_written`), then `cellport.z_test` per region and level against 1/3. The level means are compared with the saved G11 means in `gate.json`; the largest difference is reported. Descriptive, as DESIGN section 5a says; this z-test has no verdict. If the largest G11 level-mean difference is not 0, the z-test is reported as a separate run of 100 draws with the G11 seeds, not as the G11 draws.

- **Import order and thread settings.** `run_cell_a2.py` imported numpy before `cell_env`, so the numpy BLAS thread setting of the Addendum 2 run is not established by its records. This run imports `cell_env` first and records the BLAS state (`threadpoolctl`). On the new VM the import order of the Addendum 2 wrapper is reproduced once (the command below, in a shell without BLAS thread variables, output `blas-a2-order.out`; it prints the state in the main process and in one pool worker), so the state of that run can be reported. Results note section 1.7 reports this.
  ```
  python -I -c "import sys; sys.path.insert(0, 'code'); import run_cell_a2, threadpoolctl; from concurrent.futures import ProcessPoolExecutor as P; print(threadpoolctl.threadpool_info()); print(P(1).submit(threadpoolctl.threadpool_info).result())"
  ```
- **Integrity.** The wrapper checks every listed member against `data-members.tsv` (`cell_gate.g1_integrity`) before loading, and stops if it fails.

Nothing about tests, windows, seeds, P, D, gates, decision rules or predictions changes. The five tests are not rerun. The results note reports the output as filling items 1 and 2 of section 1.7 item 6, written after the results were read.

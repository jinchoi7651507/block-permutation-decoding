## 2. Why another file
DESIGN section 3 named the gate file from `Plot_Figure_2_github.m`, which plots the Fig. 2D violins from `LIP_mean_classification_net`, `FEF_mean_classification_net` and `PFC_mean_classification_net`. That script loads three files from the same folder: `Figure_2.mat`, `Figure_2_PCA.mat` and `Figure_2_decoding_accuracy.mat` (lines 3-5). The design assumed the variables were in the last one. They are not; it holds `*_mean_classification_combined` and other names. In the authors' code, `*_mean_classification_combined` is computed only in `Figure_2/code/plot_Fig2_cross_temporal_decoding.m` (lines 1609-1611), with nanmean over `Classification_net_correct` read from the same combined-time 900 ms network result files (`..._combined_time_results_more_trials_<ROI>_900ms_NN_<n>`, stored as `Classification_net_correct_comb`, line 1540) that `plot_Fig2_ET_pseudo_pop.m` averages with mean into `*_mean_classification_net` (lines 60-71, 173-175); it may hold the same values. The design names `*_mean_classification_net`, and the script that plots Fig. 2D loads it from one of its three files, so the gate reads that variable under its stamped name, from `Figure_2/plot_figure_2/Figure_2.mat` (411,320 bytes, CRC-32 ab452acd in `manifest-zenodo-10529801-figure-zips.tsv`) or, if that file lacks it, from `Figure_2/plot_figure_2/Figure_2_PCA.mat` (82,588 bytes, CRC-32 fcbe3358).

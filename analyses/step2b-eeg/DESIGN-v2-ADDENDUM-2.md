## 1. Why
- The addendum 1 pilot (`runs/graded_pilot.json`) did not achieve the target: R1–R5 gave pooled P5 power 0.84–1.00 with only 2 of 5 pilot subjects in the middle range, and the mixing steps Q30–Q48 gave power 0.00 in every subject. By the stamped rule the graded control of addendum 1 is reported as not achieved, and its pos_graded and balanced_graded arms are not run.
- A review (`review-graded-pilot-statistician.txt`) found no code error. The mixing steps were a design error: they exchanged epochs between the paired opposite-state blocks, which makes the observed eyes-closed/eyes-open vector the least favourable member of the P5 null set (null assignments that give both blocks of a pair the same label lose nothing from the exchange). The test stayed valid but strongly conservative, so its power was 0.
- Q2 of `DESIGN.md` (power of the valid rules on EEG with a graded real signal, and size-adjusted power of the invalid ones) is otherwise unanswered. This addendum makes one labelled attempt with a weakening that uses neither the labels nor the block structure.

## 2. The weakening (`code/graded2.py`)
- **N<c>:** every feature value of a subject plus independent Gaussian noise with standard deviation c × s_j, where s_j is that feature's standard deviation computed from the features alone (no labels), over the epochs kept after the equal-count subsampling of addendum 1 §3, the same in every draw. The noise is drawn independently for every epoch, feature and weakening draw. Blocks, epochs and labels are unchanged.
- **Ladder, in order:** N1, N2, N3, N4, N5, N6, N7, N8, N10, N12, N14, N16, N20, N24 (fine steps, because in synthetic checks a subject went from power near 1 to near 0 within one or two coarse steps; the steps add compute only).
- **Validity:** the noise does not depend on the labels or the blocks (s_j is the same under any block permutation), so P5 keeps the validity it has on unweakened data: exact by randomisation in balanced_graded, and as valid as on unweakened data (with the same drift caveat) in pos_graded. A synthetic check under the null in a review (40 replicates per rule) fitted an exact test.
- **What it measures:** s_j is pooled over both states, so for strongly state-dependent features the weakened effect is set mainly by c. The noise also dilutes the block-level structure, so the false-positive rates of the invalid rules in balanced_graded will be lower than in the balanced arm, and the size-adjusted power is read at that dilution. This is stated with the results.
- **What the noise is not:** c is in units of each feature's total standard deviation over both states, so the noise is largest in absolute terms on the alpha features. It is independent across features, whereas real EEG noise is spatially correlated, so c has no physical unit; it is a statistical signal-to-noise control, not a model of recording noise. The observed and null accuracies at the chosen c are reported.

## 3. Pilot subjects (`eligibility/PILOT2-SUBJECTS.txt`)
- The 5 pilot subjects of addendum 1 have now been seen under eyes-closed/eyes-open labels and are not used to choose the new rule.
- **Second-round pilot subjects:** the first 3 young and the first 2 old subjects of `eligibility/REPLACEMENT-ORDER.txt` (sub-010216, sub-010305, sub-010164; sub-010092, sub-010041), the proportions of the main draw. Because the order is a seeded random order, taking its head does not bias any later replacement. No replacement had been used (no main subject failed preprocessing; two were dropped by the epoch rule, which has no replacement).
- **Replacement order v2:** this addendum supersedes the start points of the replacement order in addendum 1 §3 (young sub-010216, old sub-010092). `eligibility/REPLACEMENT-ORDER-v2.txt` (= `REPLACEMENT-ORDER.txt` without these 5 subjects, order kept) now governs any replacement.
- **If a second-round pilot subject fails preprocessing or is dropped by the epoch rule,** it is replaced by the next subject of the same stratum in `REPLACEMENT-ORDER-v2.txt`, which then skips that subject too; the replacement takes the dropped subject's position (and so its seed index) in `PILOT2-SUBJECTS.txt`, the new list and its hash are committed before the pilot runs, and the replacement is downloaded and preprocessed in the same way and reported. The choice is therefore always made on exactly 5 subjects. The posterior alpha check does not exclude a pilot subject (reported only).
- **Facts known before any of their data are seen (from the header and marker files):** all 5 have 16 alternating 60-s blocks starting with eyes closed and the same 62 channels. sub-010216 was recorded at 500 Hz (all 45 earlier subjects at 2,500 Hz), with different software filters and a recording restart (two "New Segment" markers) before the first block; it is kept: the crop to the block span removes the restart and every file is resampled to 250 Hz by `preprocess.py`. sub-010305 has a ground impedance of 71 kOhm in its header (the 50 Hz line ratio is in its QC). The sampling rate is not a replacement criterion (this also covers the next old replacement, sub-010280, recorded at 1,000 Hz).
- Download: `code/download_pilot2.sh` (hash check of the list first; its manifest `eligibility/EEG-MANIFEST-PILOT2.sha256` hashes every raw file in the raw folder, main and both pilots). Preprocessing: the stamped `code/preprocess.py`, unchanged, on the laptop. QC summarised like the others. Not in any main table.

## 4. Pilot and choice (`code/graded_pilot2.py`)
- Command: `python graded_pilot2.py --features <features dir> --subjects ../eligibility/PILOT2-SUBJECTS.txt --out ../runs/graded_pilot2.json --workers <W>`. The script always runs the full ladder in the stated order; there is no option to run a subset. `--workers` runs the (rule, subject) tasks in parallel; every task has its own seeds, so the result does not depend on the number of workers. It checks the list against its committed hash, stops unless exactly 5 subjects can be evaluated (replace first, §3), and records which subjects were evaluated.
- As addendum 1 §5: per rule and pilot subject, 20 seeded weakenings (`default_rng([2026, 11, s, d])`), eyes-closed vs eyes-open labels, S-main, P5 only, 200 draws, null set = all 12,870 8 + 8 assignments of the 16 blocks.
- **Choice (unchanged rule):** the first rule in the ladder with pooled power in [0.20, 0.90] and per-subject power strictly between 0.05 and 0.95 in at least 3 of the 5 subjects.
- **If none: "not achieved", final** (§0).
- Stored with every test: p, the observed accuracy, the median and 95th percentile of the null accuracies, and the subject's kept epochs per block. Output `runs/graded_pilot2.json`, committed before any graded main arm runs.

## 6. Machine for the arms
- All arms of addendum 1 §4, the second pilot (§4) and the graded arms (§5) run on **one** cloud virtual machine (Google Compute Engine, us-central1, compute-optimised x86, for example c2d-highcpu-56), not on the laptop, because the laptop's cores are busy with step 2. No arm of addendum 1 §4 has run before, so all main arms share one platform. Step 2 stays on the laptop.
- **Environment:** Python 3.12.3, MNE 1.13.2, scikit-learn 1.7.2, numpy 2.5.4, scipy 1.18.1 and the other packages at the versions of the laptop environment (`pip freeze`). `runs/MACHINE.txt` records the machine type, CPU model, operating system, git commit, SHA-256 of every code file used (including `sim.py`), `pip freeze`, `numpy.show_config()` and `threadpoolctl` output (BLAS backend), the thread environment variables and the number of workers. Every worker runs with one thread (`OMP_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `MKL_NUM_THREADS=1`). `preprocess.py` never runs on the machine: filters and ICA stay on the laptop, and only feature files are moved. Laptop and machine rows are never mixed in one table.
- **Inputs:** the feature files written on the laptop by `preprocess.py` (main 40, first and second pilot) with a SHA-256 manifest (`runs/FEATURES-MANIFEST.sha256`) written before upload and checked on the machine before anything runs.
- **Equivalence check (before the pilot and the arms):** `python equiv_check.py --features <dir> --out ../runs/equiv_<machine>.jsonl` on the laptop and on the machine. It runs `run_2b.main` unchanged on `eligibility/EQUIV-SUBJECTS.txt` (sub-010134, sub-010207, sub-010308, in that order; first-round pilot subjects, in no main table): balanced arm, S-main, assignments 0 and 1 (6 rows), and one balanced_graded row (fake labels) with rule N4 for the first subject (exercises the noise weakening without eyes-closed/eyes-open labels; this rule is not chosen by this check). Each machine writes to a fresh output file. `compare_equiv.py` reports the number of rows whose p values of all rules are identical, the largest absolute difference in observed accuracy and, over the 200 stored P5 null accuracies, the largest absolute difference and the share identical. Small differences are expected (Apple Accelerate on the laptop, OpenBLAS on Linux). Whatever it shows, the arms run on the machine and the check is reported; these rows are used in no table.
- **Order on the machine:** feature manifest check → equivalence check → second pilot → commit `runs/graded_pilot2.json` → arms of addendum 1 §4 → graded arms (if a rule was chosen). Results are copied back to `runs/`; the machine and its disks are deleted.

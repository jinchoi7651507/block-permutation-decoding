# Step 2: the cloud run is the result, the laptop run is an equivalence check (written before any simulation output is read)

Written 2026-10-22 (KST), while the simulation grid of `DESIGN.md` §15 and addendum 1 was running on a laptop (cells 0–74 complete, cell 75 in progress, cells 76–176, the power pilot and the power cells not yet run). No simulation output and no Allen output had been opened when this note was committed (c5d1d41, before the cloud run started). It was revised after a statistician's review (`review-run-platform-statistician.txt`), after the cloud run had started and before any output of either run was read: the completion rule and deadline, the empty cloud `runs/`, the seed formula and the content of the equivalence check were added.

## Decision
- The simulation cells 0–176 (`runs/CELLS.json`), the power pilot, the δ choice (`code/choose_delta.py`) and the power cells are run again, from the first cell, on one cloud machine (Google Compute Engine c2d-highcpu-56, x86, Linux), with the environment installed from the laptop's `pip freeze` (Python 3.12.3, scikit-learn 1.7.2, numpy 2.5.4, scipy 1.18.1, same versions), with the stamped code unchanged (`DESIGN-v2.sha256`, `DESIGN-v2-ADDENDUM.sha256` checked on the machine before the run) and the same seeds.
- **The cloud run is the result** for all of these cells and for the power arm, including its own δ choice. This holds whatever either run shows.
- **Seeds:** cell i uses seed 2,026,000 + i; replicate r of a cell draws everything from `numpy.random.default_rng([seed, r])`, and the fold shuffle and scikit-learn's `permutation_test_score` use `random_state = r`. None of these depends on the machine or the number of workers.
- **The laptop run** of the same cells is not stopped. It is used only for an equivalence check, which changes nothing in the result: for every replicate present in both runs (same cell, same replicate index) it compares n_units, the P3 error flag and the p value of each rule, and reports per rule the share of replicates with identical p values and the largest difference. Identical values are not guaranteed: the laptop uses arm64 with Apple Accelerate and the cloud machine x86 with OpenBLAS, so rounding can move a fit near a decision boundary and a permutation p value by a step of 1/201. The laptop's own power pilot, δ choice (`runs/POWER_CHOICE.json`) and power cells are reported in the check only; if the two runs choose different δ values, power rows are compared only where δ matches, and both choice files are shown.
- **No mixing:** no table or figure combines laptop and cloud rows for the simulation cells, and the choice between the two runs is not made per cell.
- **Complete** means: every one of the 177 cells, the five power-pilot cells and the two power cells is logged `done` with return codes all 0 in the cloud `runs/run.log`, with the planned number of replicates. If the machine is stopped or lost, the run is resumed (same code, same machine type; the scripts skip replicates already written) at least once. **Only if it is still not complete at 2026-10-26 23:59 KST** does the whole simulation result (cells, power pilot, δ choice and power cells) revert to the laptop run, for every cell. This decision uses only run.log and replicate counts, never p values, and is reported. Under the fallback the laptop run is held to the same completion rule; replicates it lacks are reported as missing, never filled from the cloud run.
- **The cloud `runs/` folder started empty** except for the hash-checked `runs/CELLS.json`; no laptop row was copied to the machine. The cloud chain started at 14:40:47 UTC; when `runs_cloud/` is copied back, its file times are checked (and reported) to show that nothing older than `MACHINE.txt` (written 14:40:47 UTC by the set-up step) was present; a listing taken on the machine at 14:4x UTC, shortly after the start, showed only `CELLS.json`, `MACHINE.txt` and files of cell 0 (`run_sim_cells.py` rewrites `CELLS.json` with identical content at start).
- **Record of completion:** `runs/run.log` (return code of every worker of every cell); `chain.log` only marks the steps.
- **Allen cells** (`code/allen_cells.py`) run only on the laptop, as planned (one platform for that analysis); they are not repeated on the cloud machine.

## Machine record
`runs_cloud/MACHINE.txt`: machine type, provisioning model (SPOT, with stop on preemption), CPU model, operating system, git commit, SHA-256 of every code file used, `pip freeze`, `numpy.show_config()`, `threadpoolctl` output, thread settings (one thread per worker) and the number of workers. Cloud rows are written to `runs_cloud/` with the file names of `runs/`.

## Why
The laptop's throttled cores give about 30 more hours for the remaining cells; one cloud machine gives roughly 5–12 hours for the whole grid (measured at the start). Running the whole grid again keeps every simulation cell on one platform instead of splitting cells between two machines.

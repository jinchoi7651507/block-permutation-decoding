## Notes
- None of these defaults is wrong when calibration and held-out trials come from separate blocks with independently assigned labels (step 1 `sep24`); the problem is their combination with splits that share blocks, which every surveyed study used (practice survey 14/14). Do not write that a toolbox is wrong.
- No default offers "permute block labels between blocks, training and held-out together, and refit" — the only scheme that kept 5% in step 1 (`blk_rerun`). In scikit-learn it needs a custom permutation (e.g. permute a per-block label vector and map it to samples) passed through a loop over `cross_val_score`.

## Corrections
- 2026-10-20: the first version described CoSMoMVPA from its header comment as 'trial-level when each chunk has one label'; the code stops with an error in that case (statistician review, `review-statistician.md` must 4). Experimentalist review repeated the header reading; the code wins.
- Default splits differ by tool (both reviews): scikit-learn/MNE `cv=None` unshuffled StratifiedKFold; MNE tutorials `cv=5` or shuffled k-fold; MVPA-Light repeated shuffled k-fold; CoSMoMVPA and PyMVPA tutorials leave-one-chunk-out. Results attributed to a tool must use that tool's split as well as its permutation rule.
- 2026-10-27 (BC draft review M2; the Notes line above is kept): "None of these defaults is wrong when calibration and held-out trials come from separate blocks with independently assigned labels" is too broad. With separate blocks (step 1 `sep24`) the block-level forms were valid (fixed decoder 2.6–5.9%, training-label block form 2.9–4.6%), but the trial-level forms were not: binomial and trial-label permutation 19–30%, training-label trial form 7–14%; under GroupKFold (whole blocks held out) trial-level permutation passed 24.7% (mouse) and 16.3% (EEG). Holding out whole blocks makes block-level permutation valid, not trial-level tests.

## 2. Choices made in code (stated now); the first is a departure from the literal §4
- **P2 under S-block (stated departure from §4's "recomputed for every draw"):** the folds are the GroupKFold folds of the observed label vector's blocks, fixed across draws: a trial-level permuted vector has near-singleton "blocks", and passing the groups to scikit-learn would permute within constant-label blocks (p ≈ 1; step 2 §3 footnote). This is what a toolbox user gets. Pseudosession nulls do recompute S-block folds from each draw's own blocks, as §4 says.
- **Own trial sets:** every label vector is held over the session's kept trials with NaN outside its own set; the observed statistic and every null statistic are computed on their own trials (S-main folds = the session folds restricted to those trials, S-block folds from that vector's own blocks). The positive control follows §6: observed on real-mask trials with non-zero contrast in the real session, each null on real-mask trials with non-zero contrast in that pseudosession (draft 1 intersected the two; statistician MUST-1, IBL S1).
- **Null caching (results unchanged):** the PS-refit (S-main, S-block) and SEL-repeat null statistics of a pool member depend only on that member, so they are computed once per region-session and reused by every scored label vector (about 44k of about 71k fits saved per region-session).
- **NaN null statistics** count as exceedances in every row (conservative; scikit-learn counts them as non-exceedances, so P2 equals `permutation_test_score` only without NaN nulls, the usual case under S-main).
- **Void/root** regions are excluded (not in DESIGN; counted and reported); `region_index` counts excluded regions too (deterministic).
- **PS-fixed under S-block** is computed for the real labels only (§6 Q2); not for the fake labels (draft 1 computed it there, not in §6).
- **PS-fixed:** the decoder's held-out predictions on the scored labels (S-main per fold) are scored against each pseudosession's labels on the trials kept in that draw.
- **i.i.d. control null for the selection pipeline:** 200 trial-level permutations of the i.i.d. labels with `RandomState([2026, 34, session_index, region_index, j])`, draw j's calibration/held-out split; (a) selection repeated, (b) the selected units of the i.i.d. labels kept. Main-decoder i.i.d. rows P1, P2, P4 use rule indices 22 and 24 in the §5 seed list.
- **Sequential seeds:** `RandomState([2026, 32, session_index, region_index, label_index, rule_index])` with label_index = j for fake draw j, 20 for the real labels; rule_index 2 (P2), 4 (P4), 12 (P2 S-block), 14 (P4 S-block), 22 and 24 (i.i.d.).
- **Q2 real labels under S-block:** P1, P2, P4, PS-refit and PS-fixed, as listed in §6.
- **Positive control:** stimulus side (right = 1, left = 0) on trials with non-zero contrast; null = pool members 20–219 scored on their own stimulus sides on the real mask with non-zero contrast in that pseudosession; PS-refit only.
- **Region labels:** Beryl acronym of the unit's channel through `iblatlas.regions.BrainRegions().acronym2acronym(..., mapping='Beryl')`.
- **Run-time checks (§9, every session):** trials and mask lengths equal; the first 90 trials exactly the unbiased block and no 0.5 later; biased values only 0.2 and 0.8 after the first 90 trials (blocks are runs of equal values, so with these two values the sides alternate by construction; the alternation assert is therefore implied by the value check, verified on constructed tables); finite stimulus onsets on kept trials; spike cluster indices inside the clusters table before and after `merge_probes` and total spikes preserved (the pinned `merge_probes` offsets correctly for up to 2 probes; the freeze has 219 one-probe and 240 two-probe sessions); every cluster has an acronym. A failing session is skipped with its reason and counted.
- **Failures:** network errors retried with backoff (3 retries); any other error writes an error row and the worker continues; errors and skips are reported with denominators (§7).
- **Dispatch and cache:** sessions are claimed in order through a shared claims directory (what finishes under a time cap is close to a prefix; the prefix rule decides); each worker has its own ONE cache; after counting, only that session's folder is deleted; disk use is logged per session; before a restart, `--requeue` releases claims of sessions without a final row.
- **Pilot isolation:** the timing pilot writes to a separate file and a separate claims directory (both names must contain "pilot"; enforced), forced to 2 sessions; its rows carry pilot = true and never count as done; the run refuses to start with a non-empty claims directory. **Concurrent timing (§3):** while the 2 pilot sessions run, W − 2 processes run `--dummy-load` (synthetic region-sessions through the same code path) until the pilot ends, so t_rs includes SMT and memory contention with W processes at once.
- **Merge and indices:** the runner merges the (at most 2) probes itself with offsets = the lengths of the previous probes' cluster tables (each table asserted indexed 0..n−1), and asserts the per-cluster spike counts are unchanged by the merge (the pinned `merge_probes` offsets by the previous probe's index maximum, which is wrong from the third probe on; not used).
- **Retries:** only network failures (requests connection or timeout errors, HTTP 5xx) are retried; a failing region writes a region-error row and the session continues; a session error after a download still deletes that session's folder (deletion checked to lie inside the worker's cache; bytes freed logged).

## 3. Machine and budget (changes to DESIGN.md v1 §9, author decision 2026-10-26, before any IBL data)
- **Machine:** one Google Compute Engine compute-optimised x86 machine (e.g. c2d-highcpu-56), Ubuntu 24.04, the Python 3.12 environment above, one thread per process, a power-off after the run and a time cap; `MACHINE.txt` as in step 2 addendum 3 §2d (with the corrected provisioning-metadata path). The laptop is not used.
- **Budget:** the stamped formula is kept with C redefined: number of sessions = floor(C / (t_rs × r)), t_rs measured by the timing pilot on the same machine, r from the unit-count metadata of the first 60 sessions; **C = the core-hours that a cost cap of ₩X buys on that machine at its listed price** (X proposed below, approved by the author before the order is stamped); minimum target 30 mice unchanged (if fewer, the author decides before the run, as §9). Stop rule, cut order and "no result opened during the run" unchanged. Disk under 60 GB at any time: workers × the largest session's good-unit files must stay below 60 GB, so the number of parallel workers is set from the metadata sizes before the run (logged).
- **X = ₩40,000 (author approved 2026-10-26, before any IBL data).** C = vCPU-hours = X / (the on-demand hourly price of the machine type in its zone, read from the Google Cloud pricing page on the day of the pilot, converted at that day's KRW rate) × the number of vCPUs; price, rate, date and C are logged and timestamped with the order. c2d-highcpu-56 has 56 vCPUs on 28 physical cores: t_rs is measured in the timing pilot with the planned number of workers running at once (SMT and memory contention included), as vCPU-seconds per region-session. Workers = min(vCPUs, disk limit from the metadata sizes, RAM limit from the pilot's peak memory). A machine time cap (C / vCPUs plus 10%) is set and logged before the run; reaching it is handled by the prefix rule. The synthetic timing underestimates real cost (more units, sequential rows that run all 200 draws), so fewer sessions than a naive estimate are expected; the formula decides.

## 4. Order of work
Review of this addendum (statistician and IBL-user personas; re-review if the changes are substantial) → hash list `DESIGN-v1-CODE-ADDENDUM.sha256` (this file and the four code files) → OpenTimestamps → Bitcoin attestation → machine set-up → `prep_ibl.py order` and `regions` → `prep_ibl.py budget-meta` (unit counts only) → `prep_ibl.py realism` (trials only) → timing pilot (`run_ibl.py --pilot`, 2 sessions, p values discarded, separate output and claims, W − 2 dummy-load processes alongside) → budget outcome (t_rs, r, number of sessions, workers) and the order, region extract and realism result hashed and timestamped → attestation → the run (`run_ibl.py`) → copy back with hash check → delete the machine and its disk. Summary script written and reviewed before the run ends, before any result file is opened. Its content is fixed now: (i) rows deduplicated by (eid, region, label); (ii) the completed prefix = the largest m with sessions 0..m−1 all finished, skipped or errored, sessions beyond it dropped; (iii) per cell, NaN and errors excluded with denominators reported; (iv) Q1: the share over the 20 fake draws per region-session, then the mean per mouse, then the mean over mice; (v) F (P2 minus PS-refit, S-main) and S (SEL-fixed minus SEL-repeat) paired at (region-session, draw), S beside the same contrast in the i.i.d. control; (vi) V with the 2 × 2 verdict table, the discordant counts and the cross-tab of P2-only region-sessions against their own fake-label P2 rate (above vs below 10%); (vii) mouse-cluster BCa bootstrap (B = 20,000, seed 20261023, acceleration from the mouse jackknife), 95% and Bonferroni 98.3% intervals, "positive" = lower bound above 0, "inflated" = lower bound above 10%; (viii) region-session-weighted rates; (ix) the share of p in 0.03–0.07; (x) the realism response applied to Q2; (xi) the positive-control 2 × 2 table plus the no-value row from STIM-REGIONS.json; (xii) Extended Data region counts (regions with ≥ 3 sessions), P1 minus IID-P1, counts of excluded region-sessions and sessions with reasons; (xiii) the realised PS-refit rate on fake labels as the sanity check.
